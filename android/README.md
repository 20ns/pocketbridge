# PocketBridge Android

Native phone client for your PocketBridge Mac service. Kotlin, Jetpack Compose, Android 16 target API 36. Minimum Android 8 API 26.

## Build

Use Android Studio's bundled JDK 21 and an Android SDK with platform 36. Set `sdk.dir` in untracked `local.properties`, or export `ANDROID_HOME`.

```sh
./gradlew assembleDebug testDebugUnitTest lintDebug
```

Install `app/build/outputs/apk/debug/app-debug.apk` on your Android phone. Run Setup phone connection on the Mac (the phone needs no Tailscale), open the Mac client's pairing screen, then scan the QR using your phone camera or enter its HTTPS address and one-time code in PocketBridge. The app stores its own credential with Android Keystore encryption. It never reads Claude credentials. Android backups are disabled. Pairing sends the phone's device name so the Mac can list it; Disconnect asks the Mac to remove this phone, and a 401 shows that the Mac removed it.

Production pairing requires the Mac's HTTPS Tailscale address (Funnel, or Serve with Tailscale on the phone). The release APK blocks all HTTP, including Tailscale IP addresses and hostnames. Debug builds allow HTTP only for localhost, validated IPv4 loopback and the emulator gateway 10.0.2.2. Certificate and hostname checks are enabled, redirects are disabled, and credentials are only sent in the authorization header. This covers prompts, replies, images and background alerts.

An older HTTP pairing stays saved but cannot connect. In Settings, tap the Mac address and enter the HTTPS address from Connect phone on that Mac. The app verifies authenticated HTTPS access before saving the new address, preserving drafts and pending delivery IDs.

## Behaviour

Stop and question answers use a separate request queue, so slow reads and screenshot uploads cannot hold them up. A lost Stop acknowledgement checks current state without repeating Stop. A failed transcript read is reported while the stream stays connected and the read remains owed; a remotely deleted chat triggers a list refresh. Screenshot display retries on reconnect, and the full-screen viewer provides Back, an image count and Retry. Sub-agent rows show their status in text, the working line names running agents, and agents from a finished turn cannot become Running again on the next prompt.

Scheduled cancellation saves the prompt's text before its request. After a lost reply or app restart, the phone checks the Mac's ledger and restores cancelled text to an empty composer in the same durable write that clears recovery. Newer text, pasted blocks, images and unconfirmed sends defer restoration. Each cancelled prompt keeps its own record; deleting a chat or changing pairing clears its recovery too.

Thinking exposed by the CLI streams below the conversation while a turn runs. It disappears when the turn ends, leaving replies and tool activity in the saved transcript. Models that do not expose thinking show no thinking section.

The Mac continues Claude tasks when the phone locks or disconnects. The app receives SSE change notifications while foregrounded (and, with Alerts on, a status-only stream in a foreground service while work runs), coalesces snapshot fetches at 250 milliseconds, and reconciles on every reconnection. Each event refetches only what it changed: streaming text refetches the open chat's messages, and text for other chats refetches nothing. It caches recent chats in preferences and each opened transcript as its own file for offline reading; transcripts of chats the Mac no longer lists are removed at most every ten minutes. Prompt drafts use native asynchronous preferences, saved shortly after typing pauses and at once before a send, a chat switch or leaving the app. Unconfirmed delivery UUIDs are committed on an IO thread before any HTTP send, and survive app restarts. Snapshot serialization and disk writes stay off the typing path. If a response is lost, Retry sends the same ID, permission mode, model, effort and speed; once the Mac's transcript shows that ID, the prompt counts as delivered and is never sent again. HTTP 5xx responses preserve the ID too. HTTP mutations are single-attempt, including 503 Retry-After responses. GET snapshots and streams can recover a stale pooled connection. Mutations open a fresh connection, so idle keepalive sockets cannot spoil the first tap. A definitive 4xx rejection keeps the draft editable. The Mac's durable idempotency ledger prevents duplicate execution. Confirmed deletion commits the cached list, selected chat and delivery-state removal together, serialized with snapshot reconciliation.

Projects open first, with search, Recent/All and sorting; + in the top bar opens a panel to start a chat in any project, most recent first, to start a General chat (in the Mac's General project, for work outside any folder; it has its own row above the projects and no path, git line or Mac sessions), or to create a new project (an empty folder in the Mac's experiments folder, shown under the name field; its id is saved before sending and reused on retry, so a lost answer never makes two folders). The launcher shortcut New chat opens it too. Projects and each project's chats come back where they were scrolled, and filters, sorts and the open project persist across launches. Chats that are working or waiting for an answer anywhere are listed at the top. Select a project to start or reopen one of its chats. Every screen but Projects has a back arrow in its top bar, and the Android back gesture does the same; the page shrinks with the gesture (predictive back). A conversation shows its project's folder under the title, with a dot in the agent's colour. Claude chats carry a light orange tint and edge, Codex chats a light blue one. Projects show their own logo when the Mac finds one (cached on the phone by its version tag, old versions deleted), otherwise a letter on a colour picked from the project id. Only managed chats appear. Project folders are discovered from existing Claude Code session metadata without importing old chats; new folders can be registered in the Mac client. Recent covers the past seven days; All includes older and unused folders. Project lists offer Newest, Oldest and Name sorting; chats offer Newest and Oldest. Chat rows show the last reply as plain text and the model. New chat remains a local draft until the first prompt is sent. Typed drafts and unconfirmed first prompts stay in Recent chats; untouched blank drafts do not. Draft previews use the prompt text. Local unsent drafts can be deleted offline; an unconfirmed delivery remains protected until the Mac resolves it. Long press or the chat menu offers Rename and Delete; active chats must be stopped before deletion. Delete hides the chat with Undo for about ten seconds and then deletes it on the Mac through the same durable path (also when the app really leaves the screen; a rotation keeps the window). The deletion is saved before the chat is hidden, so one cut off by process death or a lost connection is sent at the next connection, and the chat stays hidden meanwhile; a refusal from the Mac brings it back with the reason. Rename opens with the old name selected and the keyboard up. A new chat focuses the message field. A hardware keyboard sends with Ctrl+Enter. Settings, Projects and a project's chats all pull to refresh. Haptics follow the system setting: confirm, reject, toggles, long press and the refresh threshold. Settings opens with an on/off switch for Claude Code and Codex, saved on the Mac; it moves at once, and an agent that's off leaves new chats, the model panel and the usage rings. New chats start with the last agent used while it is on, otherwise the other one. A chat whose agent is off stays readable and shows "<Agent> is off" with Turn on above the message field.

The message box grows to about 30% of the height above the keyboard (three to eight lines), then scrolls inside, so the options, Send and the conversation stay in view. Past that an expand button opens the message full screen; Back returns with the text kept. A paste of 1,000 characters or 20 lines becomes a Pasted text block above the box with its line count: tap it to read or edit it full screen, or remove it. Blocks are saved with the draft. Send puts them into the prompt text in the order pasted, before the typed message (a "/" command stays first), so the delivery id records exactly what went. Prompts over eight lines fold in the conversation with Show more and Copy.

Screenshots go in with the prompt. The image button opens Android's photo picker (up to eight per message); each image is turned upright, fitted to 2048 px and sent as JPEG 85 to the Mac as soon as it's picked, off the main thread. A failed upload shows Retry on its tile and never blocks typing; Send waits until every image is uploaded, and an image can go alone. Picked images are saved per chat and survive restarts until the Mac accepts the prompt. The upload ids, like the delivery choice below, are saved with the prompt's delivery id before sending, so Retry sends exactly the same images. Prompt images load with the app's credential, are cached on disk under the app's cache folder and decoded at display size; a tap opens a full-screen viewer. Sharing images to PocketBridge from another app opens Send to: a working chat, a recent chat, or a new chat in a recent project.

While a turn runs, typing turns the composer's end into Stop plus a split Steer button. Steer adds the message to the running turn at its next step; its arrow menu also offers Send now, which interrupts the current step and runs the message next. The choice is stored with the delivery id; if the turn already ended, the Mac runs it as a normal turn. Prompts that steered or interrupted are labelled in the transcript. When an agent's plan limit is used up (or its last turn stopped on it) and the Mac knows when it resets, Send becomes "Send at 2:02 AM": the Mac keeps the prompt and sends it once, two minutes after the reset, with the phone off. A long press on Send, or the Steer menu, offers it whenever a reset time is known, and Send now otherwise. The schedule is saved with the delivery id, so Retry repeats it, and a new chat's first prompt can be scheduled too. The prompt shows faded with its time, Send now and Cancel; Cancel puts its text back into an empty composer. The chat list shows "Scheduled · 2:02 AM". Typing "/" lists the project's commands and skills for the chat's agent, fetched once per ten minutes. A line above the composer shows the branch, lines added and removed, files changed, and ahead or behind; it refreshes when the chat opens, after each turn, on pull to refresh and every 15 seconds while shown. Sub-agents appear in the turn that started them with their model, effort, live time and activity; the working line counts running ones and prefers the agent's own summary of what it is doing. Each finished turn shows how long it worked. A project's chats list offers its Claude Code and Codex sessions from the Mac under "On your Mac"; continuing one runs that same session, so Terminal and the desktop app see what you send, and shows its last exchange dimmed under a divider.

With Alerts on (Settings; asked for on the first send), leaving the app while a chat works hands over to a foreground service of the special-use type. It keeps one status-only event stream, fetches state about once a second per burst of changes, and backs off on failure (2 seconds doubling to a minute, reset only once a stream has brought a keepalive or stayed open 20 seconds); a network change drops old connections and reconnects at once. While out of reach the Working notification says "Reconnecting to your Mac". After 15 minutes out of reach (counted on the monotonic clock, only between failures with a network and no loss of it in between) it gives up, shows a quiet "Can't reach your Mac" and leaves its last known statuses saved: a JobScheduler job looks once a network is back, posts Done, Failed, Stopped or Needs your answer for what changed, and looks again every 15 minutes while work runs that nothing watches; after a day without reaching the Mac, or an unreadable pairing twice, it stops until the app is next left. Every read is followed by a check that the pairing, alerts and the closed app still stand before anything is posted or saved, a 401 clears PocketBridge's notifications, and a waiting chat whose request changed gets its notification updated. The service restarts after its process dies (from the saved statuses), after a reboot and after an app update. A prompt scheduled for the reset gets the same job a minute after it is due, so its turn alerts too; once overdue (a sleeping Mac) it is looked at every 15 minutes. A chat list only from the cache (not yet refreshed since the app came back) can't announce Done. After any reconnect every waiting chat's request is read again, so one replaced during an outage updates its notification; a request whose notification is still up is re-posted silently. With the screen off, step lines aren't read; one look follows when it turns on. If Android refuses to start the service when the app is left, Settings says so under the switch and asks for Unrestricted battery use. It shows an ongoing Working notification: one working chat gets its title, project (or General), the step it's on (the agent's own summary, else the tool running now, as the conversation shows it) and a timer from the turn's start, with Stop (which asks for an unlocked phone; a lost reply is checked against the Mac's state before saying it didn't stop) and a tap that opens the chat. Several share one notification, counted, with a line each. On Android 16, running work asks to be a Live Update (lock screen, top of the shade and a status bar chip showing the timer, or "2 chats"; the indeterminate progress style for one chat); a chat waiting on a question, older Android versions and Live Updates turned off in Android settings get the same notification without promotion, and Settings links to that switch when it's off. A notification swiped away isn't put back until the app is left again. The timer is a chronometer, so it ticks without reposting. The step line follows step events on the same status stream: at most one look every ten seconds reads only the messages since that chat's last cursor and keeps the newest sixty. When the turn ends the notification goes and Done, Failed or Stopped takes over. It also shows "Needs your answer" with Allow and Deny for permission requests (added once the request can be read; an answer that can't reach the Mac keeps them for another try), and Done, Failed or Stopped when a turn ends. It stops as soon as nothing runs or waits, when alerts are turned off or the pairing goes, and whenever the app comes back to the screen. Turning alerts off or disconnecting also clears PocketBridge's notifications, and their actions stop answering. Samsung phones may need PocketBridge's battery use set to Unrestricted.

Model, effort, speed and permission mode are pills under the message field. Model opens a panel above the composer, at most half the screen, listing every model the Mac's Claude and Codex CLIs report: current models first, older versions below. An unsent chat can switch agent there; a saved chat keeps its agent. Effort lists only the levels the chosen model supports and hides for models without levels. Speed appears only for models whose catalog lists one (Codex's Fast) and is named by the CLI; it is a one-tap toggle, remembered per agent and sent with the prompt. Changes apply to the next prompt, including while a turn runs, and are saved per chat. New chats start from the last options used with that agent. Bypass permissions is the default. While work runs, the conversation shows the step running now and the elapsed time. Replies that end a turn have a Copy action. When the Mac reports plan usage, Projects shows each enabled agent's weekly use as a ring (Claude orange, Codex blue) and opens a breakdown per agent with reset times, credits and Codex's banked resets. Using a banked reset asks first; its idempotency key is saved before the request and reused by any retry until the Mac answers definitively, so a lost response can't spend two; Settings repeats it, and chats with a reported context, Claude or Codex, show their context window fill beside the title.

Markdown supports paragraphs, headings, nested lists, quotes, rules, bold, italic, links (web addresses only), inline code, fenced code with Copy and lightweight syntax highlighting, diffs with tinted lines, and pipe tables with their column alignment as scrollable grids. Raw HTML stays text. Consecutive tool activity collapses into one "N steps" row; each step expands to its command or input and result. Questions use native radio/checkbox options with a free-text choice, preserve unfinished choices and text across activity recreation, plan approvals render the plan, and permission requests show the full wrapped command before Allow.

A lost connection reconciles automatically. A short drop shows a quiet Reconnecting; one that repeats for a few seconds shows a persistent banner with Retry, and a phone with no network says so at once and waits for one. Reconnects back off from 1 to 15 seconds with jitter, starting over only once a stream has brought a keepalive or stayed open 20 seconds (a proxy that drops it at once still backs off and names the cause), and a network change (Wi-Fi to cellular, airplane mode off) tries again at once, dropping pooled sockets and any attempt on the old network; a rotation keeps the connection. Online means the event stream is open: state is read first, the stream opens, then the open chat's messages follow, so a long transcript can't hold the stream back. After each reconnect every saved unconfirmed prompt is checked against the Mac's ledger; one the Mac never recorded, saved within ten minutes and a normal turn (not a steer or Send now, which could land in a different turn), goes again once under its same id, and the rest keep Retry. A chat deleted here is never resent: if its first prompt is unconfirmed, the Mac's ledger decides whether the new chat is deleted there or the draft just goes. A 5xx the Mac service wrote itself (not installed, shutting down) is checked the same way, so a refused prompt returns to the composer. Failed image uploads go again once the stream is back, and a Scheduled Cancel whose answer was lost puts its text back once the Mac confirms it was cancelled. Stop and approval answers never wait behind a send. One-off failures appear as snackbars. Unconfirmed delivery appears below its bubble with Retry. Status uses one vocabulary on both clients: Ready, Working, Needs your answer, Stopping, Interrupted, Failed.

When the Mac offers it, Settings shows **Lock screen** under Mac, with Locked or Unlocked beneath it. One tap locks the Mac's screen; work keeps running. A Mac before this feature shows no row. Unlocking from the phone is not offered.

Settings offers Check latest, Download and Install for public GitHub APK releases. Downloads use a separate unauthenticated client, bounded streaming and SHA256 verification. Before Android installation, the APK must match this app's package and signing certificate and have a newer version code. Installation is confirmed by Android; update in place to preserve pairing. At launch, downloaded APKs are deleted once their version (or newer) is installed, when Android can't read them, or after three days. Images are capped at 64 MB in the cache, the outbox drops prepared images no composer holds (also at launch), and project logos keep only each project's current version.
