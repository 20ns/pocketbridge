# PocketBridge v1 contract (0.7)

HTTP JSON plus Server-Sent Events. All /api routes except /api/health and /api/pair require Authorization: Bearer <app token>. JSON errors: {error: string}. Service binds 127.0.0.1 by default; Tailscale Serve proxies it privately. Only local browser bootstrap may obtain an app token through /api/local-session, and must require actual loopback peer and same-origin request. Browser token never in URL. No arbitrary CORS.

- GET /api/health -> {ok:true, version:1}
- GET /api/local-session -> {token:string} (loopback browser only; Origin/Host validation)
- GET /api/pairing (authorized) -> {code:string, expiresAt:number, url:string, link:string}; issue short-lived one-time code. url uses configured publicUrl, default local server. link: pocketbridge://pair?url=<encoded url>&code=<encoded code>. QR SVG endpoint /api/pairing/qr can be authenticated, or QR encoded locally.
- POST /api/pair {code} -> {token:string}; one-time code exchange. Rate-limit attempts. Pairing persisted until revoked; never return Claude credentials.
- GET /api/state -> {projects:Project[], chats:Chat[], lastSeq:number, capabilities:{modes:string[], models:string[], efforts:string[], agents:Agent[]}, server:{claudeAvailable:boolean, codexAvailable:boolean, publicUrl:string}}. modes, models (default, opus, sonnet, haiku) and efforts (default, low, medium, high, xhigh, max) are the legacy Claude lists for clients before 0.5. agents carries each CLI's own catalog and version. Clients show model names from it and never offer "default" as a choice; a chat saved with model or effort "default" is shown as the catalog's defaultModel and defaultEffort. Speed names and descriptions come from the catalog too; "Fast" and "priority" are only display fallbacks.
- POST /api/projects {path,name?} -> Project. Canonical existing directory. Registration requires the local Mac master token; paired phone tokens cannot register arbitrary paths.
- One project has `general: true`: "General", for chats that belong to no project. It runs in the home folder (`generalDir`); it has no icon, its git status is `{repo:false}` and its sessions list is empty. Clients show it apart from projects (its own entry, and "General" instead of a folder name in chat headers). If the home folder was already a discovered project, that row becomes General.
- POST /api/projects/new {id,name} -> 201 Project (200 with the same project when `id` was already used). Creates an empty folder `name` in the experiments folder (`state.server.experiments`, default `~/Desktop/experiments`; null when unavailable, then 404) and registers it. Phones may call it: it can only create a new folder there. `id` is a client UUID made once per attempt and reused on retry. Names use letters, numbers, spaces, dots, dashes and underscores, start with a letter or number, don't end in a dot or space, at most 64 characters (400 otherwise); 409 if the folder exists.
- GET /api/projects/:id/icon -> 200 PNG, JPEG, WebP or GIF bytes with `Cache-Control: private, max-age=86400`; 404 when the project has none. Project.icon is an opaque tag that changes with the image, so clients key their cache on it. The Mac looks for the project's own logo one level deep in the root, public, static, assets, src/assets, app, src/app, web, docs, .github, src, resources, build and similar folders (favicon, logo, icon, app-icon, apple-touch-icon, android-chrome, ic_launcher names), Android `mipmap-*/ic_launcher*` and Xcode `AppIcon*.appiconset` within 6 levels and 400 folders (node_modules, build, dist, Pods and the like skipped). Symlinked files and folders are never followed, and the chosen file is read again at render time only if it is still a regular file inside the project; converters get a private copy. Larger, square images win; wide logos rank low. Images up to 512 px and 512 KB are served as they are; anything bigger, and ICO, ICNS (sips) and SVG (qlmanage), becomes a PNG of at most 256 px, never enlarged. The result is cached in the data folder. Icons are found in the background, one project at a time, rechecked every 10 minutes on a timer; GET /api/state never waits for them and a state event follows a change.
- POST /api/agents/:id {enabled:boolean} -> Agent. The owner's switch for claude or codex, saved on the Mac and shared by every client. An agent that is off is not probed for models or usage, its session metadata is not used for discovery, POST /api/chats and new prompts for it return 409 with "<Name> is turned off. Turn it on in Settings.", and its usage entry has no limits. Its chats stay readable; a recorded prompt id still answers as a duplicate. Clients offer only agents that are available and enabled for new chats.
- GET /api/projects/:id/git -> {repo:false} or {repo:true,branch:string|null,detached:boolean,commit:string|null,ahead,behind,files,added,removed}. Lines added and removed against HEAD within the project folder (a folder inside a larger repository counts only itself), new files counted as added (binary and files over 1 MB skipped). Recomputed at most every 4 seconds and after each turn.
- GET /api/projects/:id/commands?agent=claude|codex -> {commands:[{name,description,hint}]}. Claude: custom commands and skills from its initialize handshake run in the project folder, built-ins left out. Codex: enabled skills from app-server skills/list. A Codex prompt starting with "/<skill>" passes that skill as a skill input. Cached 10 minutes.
- GET /api/projects/:id/sessions -> {sessions:[{agent,id,title,updatedAt,preview}]}: recent Claude and Codex sessions in that folder that PocketBridge did not start (Claude session files; Codex app-server thread/list, subagent threads left out), for agents that are on.
- POST /api/chats/continue {projectId,agent,sessionId} -> Chat. Creates a chat that forks that session on its first prompt (Claude: --resume <session> --fork-session --session-id <chat id>; Codex: thread/fork), so the original keeps its history. Its last prompt and reply are copied in as messages with kind imported for context; nothing else is imported. Repeating it before the first prompt returns the same chat.
- GET /api/usage -> {agents:[{id,name,available,enabled,plan?:string,limits:[{id,label,window:'session'|'weekly'|'other',percent:0-100,resetsAt:number|null,severity:'normal'|'warning'|'critical'}],credits?:number,resets?:Resets|null,updatedAt?:number}]}. Plan limits come from each official CLI: Claude's `get_usage` control request (5-hour session, weekly, per-model weekly) and Codex app-server `account/rateLimits/read` (its windows, credit balance and banked resets). window is session for Claude's session limit and Codex's 300-minute window, weekly for Claude's weekly limits and Codex's 10080-minute window, other otherwise. Codex always has resets: Resets={available:number, credits:[{id,title:string|null,description:string|null,expiresAt:number|null (ms)}]} from `rateLimitResetCredits` (credits lists only available ones and may be shorter than available), or null when unknown, off or unanswered. Claude has no resets field. No account identity is returned. The Mac asks each CLI at most once a minute and again after a turn ends. limits is empty when a CLI is missing or didn't answer.
- POST /api/usage/codex/reset {id:<UUID per attempt>, creditId?:string} -> {outcome:'reset'|'nothingToReset'|'noCredit'|'alreadyRedeemed'}. Redeems one banked Codex reset with app-server `account/rateLimitResetCredit/consume {idempotencyKey:id, creditId}`; without creditId Codex picks one. The client makes one id per attempt and reuses it on retry, so a retry cannot spend a second reset (Codex answers alreadyRedeemed); concurrent requests with one id share one call. Usage is refreshed afterwards. 400 for a bad id, 409 when Codex is off or not installed, 502 with Codex's message when it refuses, 504 when it doesn't answer (retry with the same id). Clients confirm before redeeming.
- POST /api/chats {projectId,title?,agent?,mode?,model?,effort?,speed?} -> Chat. agent is claude (default) or codex. mode defaults bypassPermissions. Claude modes are bypassPermissions, auto, plan, acceptEdits and default; the legacy value default means Manual and maps to the Claude CLI manual flag. Codex modes are bypassPermissions, auto (workspace-write sandbox, no prompts) and readOnly. model and effort default to default; speed defaults to null (standard). Older clients may omit them.
- GET /api/chats/:id/messages -> {messages:Message[], approvals:Approval[], turns:Turn[], subagents:Subagent[], activity:string|null, thinking:string|null}. A deleted chat returns 404. turns lists each prompt that started a turn with its start and, once finished, its end; steers belong to the turn they joined. activity is the agent's own short summary of what it is doing now, while it works. thinking is readable reasoning exposed by the official CLI for the active turn only (Claude thinking blocks, Codex summaries or readable content when no summary exists). It is saved separately for reconnects and cleared when a turn finishes, stops, restarts or fails; it is never part of messages, previews or imported history. Sub-agent reasoning, signatures and encrypted or redacted content are excluded. Clients show it while the chat is running or waiting and remove it once the turn ends.
- POST /api/uploads (raw image bytes; PNG, JPEG, WebP or GIF by content, at most 5 MB) -> 201 {id,type,size}. GET /api/uploads/:id returns the bytes with their type. An upload belongs to the first chat whose prompt uses it and is deleted with that chat.
- POST /api/chats/:id/prompts {id:<client UUID>,text:string,attachments?:uploadId[],delivery?:'steer'|'interrupt',agent?:string,mode?:string,model?:string,effort?:string,speed?:string|null,projectId?:string} -> {accepted:true,duplicate:boolean,delivery?:'turn'|'steer'|'interrupt'}. attachments: up to 8 image upload ids, recorded with the delivery id and compared on retry; with attachments, text may be blank and is saved as "Look at the attached image(s)."; Claude receives them as base64 image blocks, Codex as localImage paths. While the chat is running or waiting, a prompt without delivery is 409 as before. delivery steer adds the message to the running turn (Claude takes it at its next step; Codex via turn/steer). delivery interrupt ends the running turn (pending questions are denied) and runs the message next in the same run. Either way the user message is saved first with kind steer or interrupt. If the turn has already ended, the prompt runs as a normal turn and the reply says delivery turn. Options sent with a steer or interrupt are saved for the next run; the running process keeps its own. agent applies only when the chat is created; an existing chat never changes agent (409). A known prompt id is judged against the recorded payload before any catalog lookup, so a later catalog change cannot turn a retry into a new turn. One active turn per chat; reject a new prompt while running with 409, preserve client draft. Changing mode between turns only. Persist client id before executing; no automatic re-execution after crash. When the chat id does not exist yet, projectId creates that chat and its first prompt in one transaction after every field and the project directory have been validated. A failed prompt leaves no chat. An existing chat never changes project. Omitted model and effort keep the chat's saved values; a new chat defaults both to default. model default omits the Claude --model flag and effort default omits --effort. Requests without agent come from clients before 0.5 and keep the legacy effort list. Otherwise a model must appear in that agent's catalog (Claude also accepts the aliases opus, sonnet, haiku and fable). An effort must be one that model lists; a model with no effort levels only takes default. speed is an id from the chosen model's speeds or null; anything else is 400 "Unsupported speed for this model" (Claude models have none). Omitted speed keeps the chat's, except that changing to a model without the chat's speed resets it to null (a billing tier, not a permission mode; the returned chat shows it). Without a readable Codex catalog a safe id pattern applies. When a CLI's catalog could not be read, a safe model name pattern and the known effort names apply instead. An unsupported value is rejected and is not replaced. The prompt ledger stores the agent, mode, model, effort and speed with the delivery id, and each run and Codex turn uses the options recorded with its own prompt. Options are checked again against the chat as it is after any catalog wait, so concurrent prompts cannot combine into an unsupported model, effort or speed. A retry of that id is a duplicate and does not adopt later option changes. The same id with a different payload is 409. A prompt for a deleted chat id returns 410 and must not recreate the chat.
- POST /api/chats/:id/delete {} -> {ok:true}. Idempotent for an already deleted chat. 409 while running, waiting or stopping, and does not stop that work. Removes the chat, its messages, raw events and approvals. Keeps the prompt ledger and a deletion tombstone. Emits a state event so other clients reconcile.
- POST /api/chats/:id/desktop {} -> {ok:true}. Opens a Claude chat in Claude Desktop on the Mac with `claude://resume?session=<chat id>`, the link the CLI's /desktop command uses; Desktop then lists the session. 409 for Codex chats, chats with no prompt yet, and chats with a turn running (both apps must not write one session at once); 502 if macOS could not open the link.
- POST /api/chats/:id/rename {title} -> Chat. Title is non-blank and at most 160 characters. Updates updatedAt and emits state. Renaming does not change mode, model, effort or a running turn.
- POST /api/chats/:id/stop -> {ok:true}. Idempotent; interrupt active turn; don't undo edits.
- POST /api/approvals/:id {decision:'allow'|'deny',answers?:object} -> {ok:true}. Check current pending state and owning chat.
- GET /api/events?after=<seq>[&scope=status] -> SSE. scope=status leaves out message events (streaming text) for background clients. `id: <seq>`, `event: change`, `data: {seq,chatId?,type}`. Types state,message,approval. Clients fetch current state/messages on events (coalesce at ~250ms). Keep alive comments; resume cursors and replay durable changes. Initial snapshot then stream; on reconnect fetch state and selected messages to reconcile. No token query parameter.

preview is the newest prompt or reply as plain text, at most 160 characters. context {used,window} is the token count of the chat's last request against its model's context window, from Claude's result event or Codex thread/tokenUsage/updated. Each agent runs the newest installed CLI: Claude from the configured claudePath and `claude` on PATH; Codex from the configured codexPath, `codex` on PATH and the copy bundled in /Applications/ChatGPT.app or /Applications/Codex.app (Contents/Resources/codex-cli/bin/codex). The Mac compares their `--version` (the same file reached twice is asked once; a tie keeps the configured one) at startup and with every catalog refresh, so an updated CLI and its models appear without a code change. A later check that finds none working keeps the last choice. Agent.version is the version in use. Model catalogs come from each official CLI without an API call. Claude: `claude -p --input-format stream-json --output-format stream-json --verbose --no-session-persistence --strict-mcp-config` with one `initialize` control request; its models list is kept, account details are dropped, and the "default" entry resolves defaultModel. Default effort follows `effortLevel` in ~/.claude/settings.json when the model supports it. Codex: `codex app-server` with initialize, model/list and config/read; hidden models are left out; each model's `serviceTiers` become its speeds (Claude models have none); the config model and model_reasoning_effort become defaults when listed. The last good catalog persists across restarts and refreshes every 30 minutes.

Codex chats run `codex app-server`. A chat's first run opens its thread with thread/start, or thread/fork for a continued session, and saves the thread id before any turn starts; later runs use thread/resume. bypassPermissions uses sandbox danger-full-access; auto and readOnly use workspace-write or read-only. OPENAI_API_KEY and related overrides are removed so Codex keeps its own sign-in. agentMessage items become replies, commandExecution, fileChange and mcpToolCall become tool steps with exact result ids, plan items become a plan note, and readable reasoning is temporary thinking. Indexed reasoning deltas reconcile with authoritative completed snapshots; summaries take precedence over equivalent raw text.

Claude runs use `--input-format stream-json --replay-user-messages`: each prompt is a JSON user message (text and image blocks, uuid = delivery id); steers are further user messages; interrupt sends a control_request interrupt then the next message. Messages from sub-agents (parent_tool_use_id) update that sub-agent and are not added to the chat. stdin closes once the last turn ended, no background task is running (background_tasks_changed) and every written message was replayed; a background sub-agent's completion makes the CLI start a follow-up turn first. Codex runs use `codex app-server`: thread/start, thread/resume or thread/fork with cwd, model, approvalPolicy never and the sandbox for the mode, then turn/start per prompt (with serviceTier set to the chat's speed; null is sent only when the thread last ran with a tier, since a tier sticks to the thread, otherwise it is omitted); turn/steer and turn/interrupt are sent only after turn/started. Codex replies stream from item/agentMessage/delta; thread/tokenUsage/updated gives context use; collabAgentToolCall items describe sub-agents.

Mac service owns official `claude -p` subprocesses with --output-format stream-json --verbose --include-partial-messages and --session-id for first turn, --resume for later turns. Bypass mode uses official flag; don't use --bare (it bypasses subscription auth). Pass --model and --effort only when the saved prompt value is not default. Avoid ambient API credential overrides. Chat id is UUID and is Claude session id. Use supported hooks or structured controls for approvals, test actual CLI behavior. Record raw events/normalized messages. SQLite save before broadcasting, capture stderr, buffer partial NDJSON, bound request sizes, handle missing/deleted directories, subprocess spawn failure, results/error/exit, stop/restart. Mark in-flight sessions interrupted after service restart; never auto-repeat side effects. Project.lastUsedAt is the newest known use of that folder, including a Claude session that has no PocketBridge chat. Discovery reads cwd from the Claude session index and current session files, and from the first line of the newest 300 Codex sessions (~/.codex/sessions). It skips Codex subagent threads and Codex desktop scratch folders, and does not import any conversation. Protocol implementation changes must be coordinated with other agents.
